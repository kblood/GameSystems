## Inside-pane zero ray normal: material-response audit (no change)

- Followed the new optional hit_from_inside query through canonical fire_bullet -> GlassPane.hit_by_projectile -> impact -> GlassDamageModel.assess. For a pane hit, fire_bullet forwards contact point, current direction/energy/caliber/speed; it does not forward h.normal. impact maps the point to pane-local 2D (to_2d explicitly ignores normal-depth offset), clamps to pane extent, evaluates surf_normal from authored curvature and transforms it to world space. That geometry-derived normal owns incidence, normal energy and ricochet, for inside and exterior hits alike. No fabricated ray normal or extra energy/penetration rule is needed.
- The pane result owns pass_through/ricochet/residual_velocity. Noncontinuing results stop; continuing ones append the pane RID to exclusions before the 1 mm departure and next query, so an origin still inside the slab cannot repeatedly assess that same collider. Through-hole/broken results return the incoming velocity under existing policy. Non-pane inside hits still use the first-stop dictionary; their zero normal is not used to infer a pane response.
- Nightfall _glass_feedback consumes the same ordered pane results, residual directions, stop point and 1 mm departure convention. An inside first contact can contribute a zero-length initial segment, but not a duplicate assessment or extra damage dispatch. Range accounting and the existing numerical departure convention are unchanged; this audit does not claim exact continuous thick-slab physics or verified rendering of zero-length tracer geometry.
- No new source defect demonstrated; no implementation or generated resync in this iteration. Static source review and targeted git diff --check passed. No tests/import/runtime or visual/physics QA. Previous canonical optional-parameter edits and dirty work preserved.

## Optional inside-origin ray policy (Nightfall integration)

- `GlassSystem.fire_bullet(..., params)` now accepts `hit_from_inside`, default false, and applies it to each ray query. Hosts can match their ordinary projectile ray policy without changing defaults for other consumers.
- Nightfall opts in because its normal ballistics and melee rays detect enclosing convex colliders, including corpse bodies. The glass-assisted route previously used the engine default false. First non-pane contact still stops the shared path; energy, penetration, ricochet, exclusion and damage rules are unchanged.
- Godot primary property documentation: https://github.com/godotengine/godot/blob/master/doc/classes/PhysicsRayQueryParameters3D.xml . An inside hit has zero normal; concave/heightmap exceptions remain engine-defined.
- Canonical file synchronized into Nightfall's legacy glass copy with its existing area-query adaptation retained and source hash recorded. Static review and targeted git diff --check only; no tests/runtime/imports.
