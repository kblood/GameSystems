# gs_gear_inventory licence and origin

- Licence: MIT, copyright (c) 2026 Kasper Olesen. Full text: `LICENSE` copied from the GameSystems repository root.
- Origin: original GDScript ownership ledger and Node3D scene adapter for physical game gear. It does not perform XR input, reach/occlusion queries, or rendering.
- Source of truth: `GameSystems/godot/addons/gs_gear_inventory`. Games receive generated copies with `godot/tools/sync_addons.py`; do not edit generated game copies.
- Ledger API/lifecycle: call `add_slot(id, allowed_categories, max_size)` then `register_item(id, object_ref, category, size, initial_owner)`. `store` and `retrieve` perform validated atomic ledger transitions. `capture` -> `prepare_restore` -> `commit_restore` validates checkpoints without partial mutation. `reset` returns registered items to their initial owners and `dispose` is idempotent and releases retained references.
- Scene API/lifecycle: use `NightfallGearInventorySceneAdapter` to configure `world`/hand owner roots, register physical slot anchors and items, then call `store`, `retrieve`, `capture`, `restore_inventory`, or `reset_inventory`. Items are attached at the slot anchor while stored; root `RigidBody3D` items are frozen with collisions disabled and their previous freeze, collision-layer, collision-mask, and sleeping values are restored on retrieval/reset. Linear/angular velocity is not preserved, and rigid bodies below a `Node3D` item root are not traversed. Registration captures each item's transform relative to its owner root, so reset preserves hand-relative grip placement if the hand root has moved. A physical node may represent only one item; registered items cannot be nested, and slot anchors must be unique and outside item subtrees so bulk restores cannot create scene cycles. The adapter owns transition reconciliation but not XR reach or occlusion decisions; callers must validate those before requesting store/retrieve.
- Scene-host reconciliation: the ledger's bulk reset/restore methods do not emit per-item `ownership_changed` feedback events. The scene adapter applies those bulk changes itself and emits only accepted store/retrieve transitions through its `ownership_changed` signal. Before disposing a host, detach/release its node references and dispose the ledger.
- Transition observers run synchronously; ledger mutation is rejected while `ownership_changed` callbacks are running, so a listener cannot invalidate the transition before the caller updates the scene tree.
- Adapter transition callbacks are also guarded against reentrant scene mutations. Owner roots, slot anchors and items must remain in the scene tree; reset/restore preflight rejects detached targets and cyclic parent moves before changing ledger ownership.
- Checkpoint restore requires an integer version and string owner, slot and item-claim IDs; it rejects type coercion rather than normalizing malformed values.
- Owner strings are `world`, `hand:left`, `hand:right`, or the ledger-owned `slot`. Slot/item dimensions are canonicalized by axis, allowing rotated fit checks. Stable item IDs must be unique within one inventory instance.
